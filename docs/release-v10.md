# v10.0 自适应白平衡 + 墨迹分割形状识别

日期：2026-11-01

## 一、白平衡异常（白天偏红 / 夜间正常 / 手动无效）

### 根因

1. 白平衡增益是**编译期常量** `DEF_R_GAIN=1.5625×`、`DEF_B_GAIN=1.8125×`，与光照无关。
   这组值是在夜间冷光下凑出来的，换成阳光（R 本就偏多）仍然乘 1.5625，红色被二次放大。
2. `rgb_gain_v1` 在 8bit 域做 Q8.8 乘法并饱和到 255。白天 R 原始值高，乘完直接削顶，
   红通道丢失高光层次 → 视觉上是"一片红"而不是均匀色偏；夜间信号低、不削顶，所以正常。
3. 手动档位是"在固定基准上 ±4 档 × 3.125%"，R 的可调范围只有 **1.3125×~1.781×**，
   下限仍在 1.0 以上，压不回正常值 —— 这就是"手动调节无效"的直接原因。
4. 曝光/增益固定（4.813× + 固定曝光），白天会把传感器推到饱和区，任何数字白平衡都
   救不回已经削顶的通道。

### 修改

- 新增 `rtl/cam_ae_awb.v`：去马赛克后逐帧闭环白平衡。
  - 近中性像素统计（`max-min ≤ max/4+4`）+ 样本不足时退回灰度世界，两段式避免自锁；
  - 带 6.25% 死区的增量式积分控制，**无除法器**，单帧最大步进 8/256；
  - 增益范围 0.5×~2.0×，绿色恒 1.0×。
- 手动白平衡改为直接指定增益：`96 + level×32`，范围 **0.375×~2.25×**，每档 0.125×；
  进入白平衡页即冻结自动环路，退出恢复。
- 同一模块内实现轻量 AE：每 8 帧评估亮度和削顶比例，先以 12.5% 步进调曝光
  （187~2989 行），到边界再调模拟增益档；写完等 2 帧，带死区。复用已有四相握手。
- 顶层 `cfg_*` 总线加仲裁：按键通道与 AE 通道互斥，共用一套 I2C 写接口。

## 二、形状识别准确率不足

### 绕了一圈才找对方向

第一版把固定半径 Hough 换成"连通域 + 4 个几何特征 + 决策树"，在合成轮廓上做到 0.960，
但**拿实拍照片一测就崩**。用 14 张实拍图（铅笔细线/马克笔粗线、白天窗边/室内灯、正面/斜 30°）
跑完整链路，定位到三个和分类器无关的故障：

1. **纸边框吞掉图形**：纸边与图形之间的噪点连成链，整张纸成为一个连通域（span 23910），
   被面积上限丢弃，框里的图形一起消失。
2. **粗线被 Sobel 拆成内外两层**：线宽 8px 时得到两条平行边缘，各自闭合，被当成两个目标。
3. **浅色细线的竖边先丢**：竖直边缘 |Gx| 弱于水平边缘 |Gy|，过阈值时先掉；
   矩形轮廓只剩上下两条横边，行跨度积分从 1.0 塌到 0.285。

第三条是关键：**特征在进入分类器之前就已经坏了**，加数据训练只会拟合残缺特征。

### 换的方案：墨迹分割 + 单特征

手绘图形是白纸上的暗色笔迹，不该找梯度，该找"比周围更暗"。

```
4x4 取块中心像素 -> 3x3 局部均值 - 像素 -> 阈值 -> 3x3 膨胀
-> 游程+并查集连通域 -> fill = span/(h*maxspan) -> 两个阈值
```

`fill` 是"实际面积 / 外接矩形面积"，理论值极干净：

| 形状 | 实测 | 理论 | 判定区间 |
|---|---:|---:|---|
| 三角形 | 0.50~0.54 | 0.500 | < 0.66 |
| 圆 | 0.77~0.80 | 0.785 | 0.66~0.86 |
| 矩形 | 0.86~1.00 | 1.000 | > 0.86 |

没有决策树、没有方向直方图、没有 CNN，两条比较指令出结果。

### 三条路线的最终对比（同一批 14 张实拍图）

| 方案 | 结果 |
|---|---|
| 固定半径 Hough + 固定行程（原 `shape_proc`） | 只在高对比粗线图纸上工作，细线/浅线不出框 |
| 连通域 + 4 特征 + 决策树（`shape_rec`） | 合成集 0.960，实拍图几乎全错 |
| **墨迹分割 + 填充率（`shape_ink`，采用）** | 30+ 个图形正确框出，填充率与理论值吻合 |

顺带排除的两条：32×32 图块 CNN 在合成集上 0.922（低于几何特征），需要 163k MAC/次，无优势；
全图 Otsu 阈值把 52% 像素判成前景，整幅画面糊成一个连通域。

### 修改

- 新增 `rtl/edge/shape_ink.v`：上述全流程，标签数 8 → **32**
  （实拍图里纸边/折痕会把 8 个标签占满，真图形反被丢弃）。
- 顶层 `SHAPE_LEGACY` 开关：0 = 墨迹识别（默认），1 = 旧 Hough 检测器。
- 绘制按类别着色：绿=圆、橙=矩形、红=三角形。
- 旧的决策树实现保留为 `shape_rec.v.bak`，仅作对照，不参与编译。

### 资源对比

| 资源 | v8.12（原始） | v10.0（本版） | 变化 |
| --- | ---: | ---: | ---: |
| LUT4 | 22,709 | 34,196 | +11,487 |
| FF | 12,288 | 25,324 | +13,036 |
| SRL8 | 1,165 | 1,165 | 0 |
| RAM10 | 157 | 88 | −69 |
| DSP48 | 6 | 6 | 0 |

LUT/FF 增加几乎全部来自连通域标签从 8 提到 32（12 个字段 × 32 组状态 + 32 选 1 读出）。
器件容量 60,800 cluster，本版打包后约 5 万，仍有裕量。
RAM 减少是因为关闭了在线调试。

中间过程有个坑值得记：4×4 降采样最初用"块内最小值"，需要 4 个 480×8 的行缓冲，
被综合成 15,360 个触发器，LUT 48,346 / FF 40,692，直接超出器件容量。
改成"取块中心像素"后行缓冲全免，**效果还更好**（c01 的圆从错判变正确）。

## 五、注意事项

- 本版关闭了在线调试（`enable-mark-debug=0`）。需要抓内部信号时改回 1 并恢复
  `debug_profile.wizard.json`，同时重新编译。
- 识别对旋转不敏感（填充率是形状不变量），限制在别处：轮廓需基本闭合、
  外接框 ≥ 14×14 采样点（全分辨率约 56×56）、目标之间不能重叠。
- 识别阈值跟随按键档位（`th_low + 8`），纸面特别暗或笔特别浅时需要人工降档。
- 白平衡在画面里几乎全是彩色物体时可能无法锁定（近中性点不足），属算法固有边界。
