# 形状识别：从边缘图到墨迹分割

本文件记录识别方案为什么换掉、换成什么、以及换的代价。

## 一、旧方案为什么不行

最初的 `shape_proc` 用固定半径的 Hough 圆检测 + 固定行程的矩形判定 + 5 种长宽比假设。
参数是按"打印靶纸、线条规整、目标必须完整"这一前提调的，一旦目标尺寸/角度/线条质量变化就失灵。

第二版 `shape_rec` 改成"Sobel 边缘 → 4×4 降采样 → 游程连通域 → 4 个几何特征 → 决策树"，
在合成轮廓上做到 0.960，但**拿到实拍图上完全不可用**。原因是训练分布和实拍分布不一致：

| 合成轮廓 | 实拍手绘 |
|---|---|
| 1 px 干净闭合线 | 2~6 px 马克笔线，带纸纹、反光、褶皱 |
| 单一目标居中 | 多个目标，常贴边被裁 |
| 背景纯黑 | 白纸有明暗渐变 |

更具体地说，在实拍图上跑完整链路后发现了三件事：

1. **纸边框把图形吞掉**。纸的边缘和图形之间的噪点连成一条链，整张纸变成一个连通域（span 23910），
   被 `MAX_SPAN` 丢弃，框里的图形也一起消失。
2. **粗线被 Sobel 拆成内外两层**。线宽 8 px 时得到两条平行边缘，各自闭合，被当成两个目标。
3. **浅色细线的竖边先掉**。竖直边缘的 |Gx| 比水平边缘的 |Gy| 弱，过阈值时先丢，
   于是一条矩形轮廓只剩上下两条横边，行跨度积分 span 从 1.0 塌到 0.285。

第三条最致命：**特征在进入分类器之前就已经坏了**，再训练也救不回来。

## 二、换成的方案：墨迹分割

问题的根源是"用梯度找轮廓"。手绘图形是白纸上的暗色笔迹，因此不该找梯度，而该找**比周围更暗的像素**。

```
灰度 1920x1080
  -> 4x4 取块中心像素          480x270
  -> 3x3 局部均值 - 当前像素    "比周围暗多少"
  -> 阈值 (默认 18)            墨迹掩码
  -> 3x3 膨胀                  连上 1px 断口
  -> 游程 + 并查集              连通域
  -> fill = span/(h*maxspan)    单特征
  -> 两个阈值                   三角/圆/矩形
```

三步关键差异：

**（1）局部均值减像素，而不是 Sobel。**
`mean - pixel` 是各向同性的：竖线、横线、斜线的响应一样强。Sobel 的 |Gx| 和 |Gy| 对不同方向响应不同，
细竖线天然吃亏。而且局部均值自带光照归一——纸面从 200 渐变到 120，减完还是同一个数，
不需要额外做自动曝光或直方图均衡。

**（2）4×4 取中心像素，不取最小值、不做平均。**
一开始用块内最小值（怕丢细线），实测反而更差：最小值把纸面的暗噪点放大，外接框被撑大，填充率被拉低。
中心点采样在 14 张实拍图上框出 47 个目标，最小值只有 45 个，而且 c01 的圆从"错判成三角"变成"正确"。
副产品是完全不需要行缓冲，省了 15360 个触发器。

**（3）只用一个特征：填充率。**

```
fill = span / (h * maxspan)
```

`span` 是逐行"该连通域在本行的最左到最右"的累加，等于轮廓**围起来的面积**（不是线条面积）；
`maxspan` 是最长的那一行的跨度；`h` 是外接框高度。

几何上这就是"实际面积 / 外接矩形面积"，理论值非常干净：

| 形状 | fill 实测 | 理论 |
|---|---:|---:|
| 三角形 | 0.50 ~ 0.54 | 0.500 |
| 圆 | 0.77 ~ 0.80 | 0.785 (π/4) |
| 矩形 | 0.86 ~ 1.00 | 1.000 |

分界取 0.66 和 0.86，两条比较指令，没有决策树、没有方向直方图、没有 CNN。

分母用 `maxspan` 而不是外接框宽度 `w`，是因为实拍图里外接框常被旁边的噪点撑大，
`w` 偏大，`span/(w*h)` 会把正方形算成 0.72——正好落进圆的区间。换成 `maxspan` 后这类误判消失。

## 三、和另外两条路线的对比

同一批 14 张实拍图（覆盖铅笔细线、马克笔粗线、白天窗边、室内灯、正面和斜 30°）：

| 方案 | 结论 |
|---|---|
| 固定半径 Hough + 固定行程（`shape_proc`） | 只在高对比粗线图纸上工作，细线/浅线完全不出框 |
| 连通域 + 4 特征 + 决策树（`shape_rec`） | 合成轮廓 0.960，实拍图几乎全错（纸边吞并、双层轮廓、span 塌陷） |
| **墨迹分割 + 填充率（`shape_ink`，采用）** | 14 张图里 30+ 个图形正确框出，且可解释 |

此外还试过但没采用的：

- **YOLO 风格 32×32 CNN**：合成集 0.922，比几何特征低，且需要 163k MAC / 次推理。精度不占优，不划算。
- **全图 Otsu 阈值**：白纸光照不均，Otsu 把 52% 的像素判成前景，整幅画面变成一个连通域。
- **闭运算 + 开运算**：对纸边框吞并有帮助，但会削掉细线，且形态学窗口在 RTL 里更贵。

## 四、RTL 实现要点

`rtl/edge/shape_ink.v`：

- 4×4 采样：`colsub/subrow` 计数器，`(1,1)` 位置锁存
- 3×3 局部均值：两级行缓冲 `gb0/gb1`，纵向求和后做 3 点滑窗，`/9` 用 `×57 >> 9` 近似
- 对齐：局部均值因滑窗固有滞后 1 个像素/行，原像素经两级延迟 `g4_r1/g4_ref` 对齐到同一位置
- 膨胀：`mask_bit = raw | m_prev | m_up | m_upr`，因果 3×3，只需要 1 行缓冲
- 连通域：与 `shape_rec` 相同的游程 + 并查集，标签数从 8 提到 **32**
- 帧末：每个连通域一次 32 拍除法算 `fill`，两条比较出类别
- 绘制：按类别着色（绿=圆、橙=矩形、红=三角形）

**标签数为什么必须 32**：实拍图里纸边、折痕、阴影会在 8 个标签内把位置占满，
真图形反而被丢弃。实测 `LABELS=8` 时 c09/c10/c11 三张图**一个框都出不来**，32 时全部正常。

## 六、已知边界

1. **主特征假设轮廓闭合**。线条断开超过膨胀能补的距离（约 2 个采样点）时，`span` 会偏小，被判成三角形。
2. **目标外接框需 ≥ 14×14 采样点**（全分辨率约 56×56），更小的会被 `MIN_WH` 过滤。
3. **fill 对"轮廓形状"敏感，对旋转不敏感**——正方形转到 45° 仍然是 1.0，圆仍然是 0.785，
   三角形仍然是 0.5。这一点比旧版"±30° 以内"宽松得多。
4. **重叠的目标会并成一个连通域**，此时 fill 落在两者之间，可能判错。
5. 阈值是全局的，靠按键调整。纸面特别暗或笔特别浅时需要人工降阈值。
