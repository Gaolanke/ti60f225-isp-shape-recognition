# 白平衡异常的根因与修复

## 现象

- 白天有阳光、室内靠窗等**暖光/高色温混合**场景：画面整体偏红，白色物体明显发橙。
- 夜间只有冷色（高色温）灯光：颜色正常。
- 用按键进入白平衡页手动调 R/B：几乎看不出变化，压不回正常。

## 逐条定位

### 1. 白平衡是编译期常量，不随光照变化

`rtl/ti60f225_oob_top.v` 旧版本：

```verilog
localparam [15:0] DEF_R_GAIN = 16'd400;   // 1.5625x
localparam [15:0] DEF_G_GAIN = 16'd256;   // 1.00x
localparam [15:0] DEF_B_GAIN = 16'd464;   // 1.8125x
```

这三个值直接送进 debayer 里的 `rgb_gain_v1`，与场景无关。它们是在**夜间冷光**下凑出来的：
冷光里 R 分量天然偏少，乘 1.5625 刚好补平，所以夜间正常。换成阳光（R 天然偏多）后仍然乘
1.5625，红色被二次放大 → 偏红。

### 2. 8bit 域削顶放大了偏色

`rgb_gain_v1` 是 Q8.8 定点乘法，结果饱和到 255：

```verilog
wire [P_DEPTH-1:0] out_high = (|mul_high[Q_WIDTH+P_DEPTH-1:P_DEPTH+8]) ? 2**P_DEPTH-1 : ...
```

白天 R 原始值本来就高（例如 180），×1.5625 = 281 → 削到 255；G 仍是 150、B 约 217。
结果是 R 通道**丢失全部高光层次并贴顶**，视觉上就是"一片红"，而不是均匀的色偏。
夜间信号幅度低（R≈90），×1.5625 = 141 不削顶，所以看不到这个问题。

### 3. 手动调节的窗口根本不够用

旧的手动档位是"在 DEF 基础上 ±4 档、每档 3.125%"：

```verilog
wire [15:0] wb_r_trim = DEF_R_GAIN - 16'd64 + {9'd0, wb_r_level_px, 3'b000};
```

即 R 只能调到 **1.3125x ~ 1.781x**。阳光场景需要的是 R ≈ 0.8x（甚至更低），
这个窗口的下限还在 1.0 以上，所以怎么按都救不回来 —— 这就是"手动白平衡无效"。

## 修复方案

新增 `rtl/cam_ae_awb.v`，在**去马赛克之后的 RGB 上做逐帧闭环**：

1. **统计**：每 8 个 beat（16 像素）、每 8 行取一个采样点，只在"近中性像素"
   （`max-min <= max/4 + 4`）上累加 R/G/B。这样大面积彩色物体不会把统计拉偏。
2. **兜底**：如果近中性点太少（说明当前白平衡偏得离谱），自动退回全画面灰度世界
   （gray-world）做粗调，收敛后再切回近中性精调。两段式避免了"偏色 → 没有中性点 →
   统计不到 → 更偏"的自锁。
3. **控制**：逐帧比较 S_R / S_G / S_B，带 6.25% 死区的增量式积分控制。
   全程只有比较、移位、加法，**没有除法器**。
4. **范围**：增益限制在 0.5x ~ 2.0x，绿色恒为 1.0x；单帧最大步进 8/256，不会跳变。
5. **手动优先**：进入调节模式的白平衡页后 `i_man_en=1`，环路冻结、AE 停止发请求，
   手动档位直接给出 **0.375x ~ 2.25x**（96 + level×32，每档 0.125x）的增益。
   范围和方向都覆盖实际需要，退出该页即恢复自动。

### 顺带修掉曝光工作点

固定 4.813x 模拟增益 + 固定曝光，在白天会把传感器推到饱和区，任何数字白平衡都救不回
已经削顶的通道。因此在同一模块里加了轻量 AE：

- 每 8 帧评估一次平均亮度与削顶比例（削顶像素 > N/32 即判过曝）；
- 先以 12.5% 步进调曝光（187 ~ 2989 行），曝光到边界再调模拟增益档；
- 写完等 2 帧稳定再评估，带死区，不会来回抽动；
- 手动调节模式下 AE 自动退出。

AE 通过已有的四相握手接口写入 `cam_cfg_sched`，没有新增 I2C 时序逻辑。

## 验证

`sim/tb/tb_cam_ae_awb.v` 把 DUT 输出的增益乘回场景再喂回去，构成和实板一致的闭环：

| 场景 | 原始 R/G/B | 收敛后增益 | 输出 R/G/B | 偏差 |
| --- | --- | --- | --- | --- |
| 白天暖光 | 205/155/110 | R=206 B=383 | 164/155/164 | 5.8% |
| 夜间冷光 | 105/150/200 | R=344 B=207 | 141/150/161 | 6.0% / 7.3% |
| 切回白天 | 205/155/110 | R=206 B=340 | 164/155/146 | 5.8% |

- 死区 6.25%，实测残差 ≤ 7.3%，落在死区量级内；
- 手动增益直通且 30 帧内不被环路改写；
- 过曝场景触发曝光下调（0x0BAD → 0x08F1）。

对比旧固件在同一组场景下的表现（R 固定 1.5625x、8bit 削顶）：白天通道偏差超过 60%，
夜间约 4%，与用户描述的"白天偏红、夜间正常"完全吻合。

## 上板注意事项

- 首次上电约 30 帧（0.5 s）完成白平衡收敛，期间画面会有轻微色温漂移，属正常。
- 若某个特定光源下仍偏色，先看 `awb_locked`（LED 指示）是否点亮：
  未点亮说明近中性点不足，通常是画面里全是彩色物体，属于算法固有边界。
- 手动档位现在是"直接指定增益"，不再是在固定基准上微调；退出白平衡页即恢复自动。
